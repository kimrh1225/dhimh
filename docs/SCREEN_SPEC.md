# 화면 구성 및 UI 명세

## 디자인 방향
한국어 우선, 읽기 쉬운 교육용 문서 인터페이스. 중립적인 대비·일관된 타이포그래피·모바일 대응. AI 권위성을 과장하는 '합격/불합격' 점수·확정 판정 배제. 모든 상태는 색상과 별개로 텍스트 레이블 필수.

## S1 홈 `/`
- 헤더: 작업명, 'AI는 최종 판정자가 아닌 검토 보조' 안내.
- 내 연구계획 리스트: 로컬 저장된 제목·분야·최신 저장일·버전 수, 비어 있음 상태.
- '새 연구계획 작성' CTA, 브라우저 데이터 보관/삭제 안내.

## S2 작성 `/plans/new`, 편집 `/plans/[id]`
- 필드: 제목*(2~120자), 분야*(`math|physics|chemistry|biology|computing|other`), 연구 질문*(10~3000자), 가설(0~3000), 연구 방법*(10~6000), 독립 변수(0~2000), 종속 변수(0~2000), 통제 조건(0~2000), 예상 결과·해석 계획(0~3000), 자원·시간 제약(0~2000).
- 필수값 '*' 표기, 각 필드 설명/예시(입력 자동 생성 기능 없음), 실제 입력 데이터는 생성하지 않음.
- 저장/수정 취소/검토 버튼. 새 버전은 현재 버전과 내용이 다를 때만 생성. 수정 중 변경내용 이탈 경고.
- 버전 타임라인은 생성 시각과 당시 분야/제목 표시. 버전 선택 시 읽기 전용 원본.

## S3 분석 결과 `/plans/[id]`의 '피드백' 탭
- 상단: 분석된 버전 ID, 모델/프롬프트/루브릭 버전(표시 가능한 범위), 생성 시각, 보조 도구 고지.
- 6개 기준 카드: 상태·근거 인용·검토 이유·개선 질문·가능한 조치·불확실성.
- 상태 문자열: `adequate=적절함`, `needs_revision=보완 필요`, `insufficient_information=정보 부족`, `not_applicable=해당 없음`.
- '전체 비판적 질문' 영역, 추가 검토가 필요한 이유.
- 정보 부족 시 임의로 빈칸을 가정해 채워 넣지 말 것.
- 실패 상태: 오류 유형·재시도·기존 검토 보존.

## S4 비교 `/plans/[id]/compare`
- 좌측 이전 버전, 우측 선택 버전(모바일 세로 배치), 필드별 추가/삭제/유지 구간 강조.
- 리뷰는 해당 버전 링크를 통해 열기; 여러 버전의 품질 향상을 자동 추론하거나 향상 수치를 만들어 내지 않음.
- 버전이 하나뿐이면 '수정 버전을 저장한 뒤 비교할 수 있습니다.' 표기.

## 필수 상호작용·접근성
- 모든 input/textarea에 `label` 및 오류와의 연결, 비동기 상태는 `aria-live` 사용.
- 아이콘만 있는 컨트롤은 `aria-label`, 탭은 키보드 이동 가능.
- 리뷰 요청 전에 '이 연구계획 내용이 외부 AI 제공자에게 전송됨' 체크 표시. 동의 안 하면 호출 불가.
- 휴지통 삭제는 확인 다이얼로그와 되돌릴 수 없다는 설명.
