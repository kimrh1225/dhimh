# 테스트 및 검수 계획

## 1. 자동화 원칙

- 모든 자동 테스트에서 실제 OpenAI API 호출 금지(`MOCK_AI=true`, `OPENAI_API_KEY` 불필요).
- 실제 API 수동 점검은 사용자 승인 뒤 별도 1~2개 **합성 데이터** 사례로 진행. 사용량·응답 스키마·비용 기록.
- 검증 단계: `npm run lint`, `npm run typecheck`, `npm run test`, `npm run test:e2e`, `npm run build` (Codex가 package.json에 표준 스크립트 구현).
- `feedback.schema.json` 스키마 검사(예: AJV)와 추가 비즈니스 규칙 테스트를 분리.

## 3. API 통합 테스트

| ID | 요청 | 예상 |
|---|---|---|
| IT-01 | 정상 plan+동의(true), mock | 200, UUID, 6개 기준, provider=mock |
| IT-02 | 유효한 plan+동의(false) | 400 CONSENT_REQUIRED, 모델 미호출 |
| IT-03 | 유효하지 않은 JSON | 400 VALIDATION_ERROR |
| IT-04 | 요청 본문 64KB 초과 | 413 PAYLOAD_TOO_LARGE |
| IT-05 | 실모드·키 미설정 | 503 AI_UNAVAILABLE |
| IT-06 | LLM 거절/실패/시간 초과 mock stub | 422/502/504 계약에 따른 안전한 오류 |
| IT-07 | 동일 필드 문자열에 공격 지시 포함 | 서버가 정책/스키마 무시하지 않음 |

## 4. Playwright 핵심 E2E

- E2E-01: 홈 빈 상태 → 계획 생성 → 브라우저 리로드 후 v1 복구.
- E2E-02: 필수 필드 누락 → 저장 및 분석 실행 차단.
- E2E-03: 동의 거부 → AI 호출 없음 → 동의 후 mock 피드백 생성.
- E2E-04: 평가 카드 6개/4가지 상태 문구/질문/불확실성 노출.
- E2E-05: v1 수정 → v2 저장 → 비교 → v1/피드백 원본 유지.
- E2E-06: 삭제 확인 → 계획·버전·리뷰 전체 제거.
- E2E-07: 분석 실패/새로고침/브라우저 뒤로 가기에서도 입력 손실 없음.
- E2E-08: 키보드 탐색·초점·모바일 화면·오류 접근성 점검.

## 5. 데모 승인 게이트

- 필수 P0 기능 전부 시연됨, 빌드·유닛·통합·E2E 검사 통과(실행 환경 제약이 있으면 미검증으로 명시).
- API 키가 번들/커밋/브라우저 네트워크 응답에 노출되지 않음.
- 사용자의 외부 전송 동의가 없으면 AI 호출하지 않음.
- 생성형 AI가 연구 질문을 바꾸거나 계획 자체를 자동으로 완성하지 않음.
- 6개 기준 출력에서 정보 부족과 비적용을 구분할 수 있음.
- 실제 학생 개인정보 또는 미공개 연구 아이디어로 공개 데모하지 않음.
- 비교평가 결과가 없으면 개선 효과를 주장하지 않음.
