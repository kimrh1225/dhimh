# 제품 요구사항(PRD)

**제품 작업명**: R&E Research Plan Feedback | **버전**: v1.0 | **상태**: 구현 전 명세

## 1. 문제 및 목적

영재학교 학생은 R&E 연구계획을 수립하면서 연구 질문, 가설, 연구 방법, 변수 통제와 실행 가능성에 대한 전문 피드백을 제때 받기 어려울 수 있다. 이 문제는 실제 학습자 조사로 입증된 것이 아니라 첨부 문서의 **가상 인터뷰(13개 문항)**에서 제안된 탐색적 가설이다.

MVP는 학생이 작성한 계획을 구조화된 기준으로 검토하여 강점, 보완할 점, 정보 부족을 구분하고, 학생이 스스로 수정하는 데 필요한 질문·근거를 제시한다. 추가적으로 같은 계획에 대한 일반 ChatGPT 방식·구조화된 ChatGPT 방식·본 앱의 품질을 탐색적으로 비교하는 연구를 수행한다.

## 2. 대상 사용자·핵심 과업

- 주요 사용자: R&E 연구계획을 작성 또는 수정 중인 영재학교 학생.
- 연구 평가 사용자: 앱 사용자나 연구 결과를 평가하는 소규모 평가자(앱의 별도 로그인/관리 화면은 제공하지 않음).
- 핵심 JTBD: '내 연구 질문/방법이 연결되는지 확인하고, 무엇을 다시 생각해야 하는지 파악하며, 수정 전후 변화를 확인하고 싶다.'

## 3. 기능 요구사항 / 우선순위

| ID | 우선 | 기능 | 검수 가능한 인수조건 |
|---|---|---|---|
| FR-01 | P0 | 구조화된 계획 작성 | 제목, 분야, 질문, 방법 필수; 나머지는 선택; 빈칸과 유효성 오류 구별; 저장 후 재접속 유지 |
| FR-02 | P0 | 로컬 버전 저장 | '새 버전 저장' 시 v1→v2 증가, 기존 버전 불변; 최근 편집 초안 복구 |
| FR-03 | P0 | AI 검토 요청 | 유효한 계획과 명시적 외부 전송 동의가 있어야만 호출; 진행/실패/재시도 상태 제공 |
| FR-04 | P0 | 항목별 구조화 피드백 | 6개 기준별 `적절함/보완 필요/정보 부족/해당 없음` 상태, 근거, 이유, 개선 방향과 불확실성 표시 |
| FR-05 | P0 | 비판적 질문 | 연구계획을 재점검하는 질문 목록 제공; 학생에게 자동 수정 강요 금지 |
| FR-06 | P0 | 이전/수정 버전 비교 | 선택한 두 버전 필드별 텍스트 비교; 원문 보존; 분석 결과와 대상 버전 연결 |
| FR-07 | P0 | 데이터 통제 | 브라우저 내 저장 사실 명시, 전체 데이터 삭제·확인, 비밀키 비노출, 서버 원문 미저장 |
| FR-08 | P0 | 오류·불확실성 UX | 미입력/거절/모델 오류/시간초과/네트워크 실패에 대해 구별 가능한 안내 |
| FR-09 | P1 | JSON/텍스트 내보내기 | 별도 확인 후 로컬 파일로 저장, 기본적으로 개인정보 제외 권고 |
| FR-10 | P1 | 평가 자료 익명 내보내기 | 자발적·동의 받은 데이터만 별도 내보내고 자동 수집하지 않음 |

## 4. 비기능 요구사항

| ID | 내용 | 검증 방법 |
|---|---|---|
| NFR-01 | TypeScript strict와 입력·응답 런타임 검증 | typecheck/단위 테스트 |
| NFR-02 | 앱 핵심 경로 키보드로 조작, 오류와 상태는 색상 외 텍스트로 안내 | 접근성 수동 점검 및 E2E |
| NFR-03 | 실제 모델 비연결 mock 시나리오 재현 | MOCK_AI E2E |
| NFR-04 | 서버는 민감한 요청 본문을 로그/DB/분석 도구에 보존하지 않음 | 로깅 리뷰/테스트 |
| NFR-05 | 계획 1~10개, 각각 최대 20개 버전 규모에서 페이지 기능 정상 | 로컬 성능 점검(수치는 개발용 목표) |
| NFR-06 | 사용자가 외부 전송을 명확히 이해할 수 있음 | 안내 및 동의 동작 테스트 |

## 5. MVP에 포함하지 않는 것

학습 콘텐츠 추천, 범용 AI 채팅, 학술 검색/RAG, 외부 전문가 매칭, 연구 결과 자동 생성, AI가 사용자를 대신해 연구계획 재작성, 자체 LLM 학습/파인튜닝, 공동 편집, 로그인/서버 동기화, 앱 내 비교실험 자동 실행.

## 6. 출시(데모) 완료 기준

- 필수 E2E: '계획 생성 → 저장 → 평가(mock) → 피드백 확인 → 학생 수정 → 버전 비교 → 삭제' 통과.
- 보안/개인정보: API 키 브라우저 노출 없음, 명시적 외부 전송 동의, 본문 로그 미저장, 데이터 삭제 확인.
- 6개 기준 출력 스키마 및 사실 인용 검증; 실패 시 안전한 메시지 표시.
- 비교 실험을 위해 표준화된 평가 프로토콜과 합성 테스트 케이스 준비(실제 참가자·결과는 자동 생성하지 않음).
- 8주 회고/기능 시연 가능. 데이터와 학습 성과 관련 주장은 실험에서 얻은 관찰 범위로 제한.

## 7. 성공 판단 지표(목표값이 아닌 측정 항목)

기능 완수율, 생성된 피드백의 문제 발견 정밀도/재현율(전문가 기준 답이 있는 경우), 부정확한 지적 비율, 제안의 실행 가능성, 정보 부족 인정 비율, 학생의 변경 반영·이해도, 과업 완료 가능 여부, 주관적 유용성. 표본과 측정 방식은 `EVALUATION_PLAN.md` 참조. **개선 효과를 사전 보장하지 않는다.**
