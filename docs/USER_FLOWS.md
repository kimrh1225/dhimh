# 사용자 흐름 및 상태 전이

## F1. 첫 이용과 계획 생성
1. `/`에서 '새 연구계획' 클릭 → `/plans/new`.
2. 학생이 분야·제목·연구 질문·방법을 입력. 가설, 독립/종속 변수, 통제, 예상 결과, 자원·기간은 연구 성격에 따라 비워 둘 수 있음.
3. 필수값 오류는 해당 입력란 근처에 표시. 저장 클릭 시 계획 v1 및 편집 초안을 브라우저 IndexedDB에 저장하고 상세 화면으로 이동.
4. '저장 완료: 이 기기의 브라우저에만 보관됩니다' 안내. 다른 기기에서 자동 동기화되지 않음.

## F2. 계획 검토
1. `/plans/[id]`에서 불변 버전 선택 후 'AI 검토' 클릭.
2. 외부 LLM 전송 범위와 비공개 연구 아이디어 보호 경고 확인. 체크/동의는 **요청별**로 받아야 함(기존 동의 상태로 자동 재호출 불가).
3. POST `/api/reviews`; 대기 중 요청 중복 방지, 로딩·중단 안내. 성공 시 JSON 스키마 검증 및 해당 `planVersionId`와 함께 로컬에 저장.
4. 기준별 카드/3분류/추가 질문 표시. 별도 '해당 없음'은 가설이나 변수 관점이 비적용인 연구 분야에서 사용.
5. 실패/거절/시간초과 시 원문·기존 분석 보존, 오류와 다시 시도 선택.

## F3. 피드백을 반영한 수정
1. 학생이 v1을 참고해 편집 모드에서 텍스트 **직접 수정**.
2. '새 버전 저장' 클릭 시 v2 생성. 변경점이 없으면 새 버전 생성하지 않고 안내.
3. `/plans/[id]/compare?from=...&to=...`에서 필드별 강조 차이 확인, 이전 버전 변경 불가.
4. 기존 분석은 v1에 고정되며 v2를 자동으로 '개선됨'이라고 판정하지 않는다. 필요시 v2 검토를 **별도로** 요청한다.

## F4. 삭제 및 오프라인 모드
1. 계획 상세 또는 설정에서 '삭제' 클릭 → 영향(모든 버전 및 리뷰 삭제) 명시 → 확인 후 IndexedDB에서 제거.
2. AI 서비스 장애·키 미설정에도 기존 로컬 입력·비교는 가능. 모델 분석은 불가하다는 메시지 표시.

## 상태 모델

- Plan: `draft`(아직 버전 저장 전), `saved`(1개 이상의 불변 버전 존재).
- Review: `idle`, `consent_required`, `loading`, `succeeded`, `failed`, `refused`.
- Compare: 버전 두 개 이상이면 가능; 1개만 있을 때 가이드 메시지.
- 서버 성공 응답이 도착한 뒤 사용자가 다른 버전으로 이동했어도 요청한 버전 ID에 결합한다.

## 예외

- 새로고침/탭 종료: 최신 저장 버전과 최근 편집 초안 복구.
- 브라우저 저장 용량 초과/프라이빗 모드: 저장 실패를 명시하고 텍스트 수동 복사 가능하게 원문 유지.
- 네트워크 중단: 기존 분석 기록 유지, 중복 요청 방지.
- AI가 자료 부족을 판단: `insufficient_information`과 필요한 추가 정보 질문을 생성.
- 순수 수학/이론 연구: `variables_controls` 항목을 억지로 실험 통제로 판단하지 않고 `not_applicable` 허용.
