# 8주 구현 로드맵

**총 우선순위**: 기능적 완결성 및 비교평가 가능성을 함께 확보. 매주 작은 검증을 남기고, 한 단계 통과 뒤 다음 단계 진행. Codex 작업 카드는 `../codex/tasks/` 참조.

| 주 | 구현 목표 | 산출물/완료 게이트 | 대표 테스트 |
|---|---|---|---|
| 1주 | 프로젝트 기반·디자인 틀·Mock AI | Next.js+TS+Tailwind 초기화, 라우팅, 프로젝트 규칙, lint/typecheck/test/e2e script, fixture mock | `01-foundation` |
| 2주 | 계획 입력 및 브라우저 저장 | 필드 검증, IndexedDB 저장/리로드, v1 생성, 폼 오류/초안 복구 | `02-input-persistence` |
| 3주 | AI API·스키마·보안 경계 | 동의 체크, `/api/reviews`, mock/live adapter, 에러·타임아웃, JSON Schema 검증 | `03-ai-review` |
| 4주 | 피드백 화면·비판적 질문 | 6개 루브릭 카드, 상태 구분, 근거·불확실성·질문 표시, 빈 상태 | `04-feedback-ui` |
| 5주 | 학생 수정·버전 비교 | v2/v3 생성, 원본 불변, 필드별 diff, 버전별 평가 연결 | `05-revision-compare` |
| 6주 | 에러·보안·접근성 강화 | 삭제, 로그 검토, 키 비노출, 저장 실패 UX, E2E 회귀 | `06-hardening` |

| 8주 | 최종 시연·문서·보고용 자료 | README 실행 검증, P0 회귀, 시연 스크립트, 실제 수행한 평가 범위 정리 | `08-final-demo` |

## 필수/선택을 가르는 규칙

- **P0** 기능: 입력 → 검토 → 피드백 → 수정 → 비교 → 삭제, 예외/프라이버시 처리. 한 기능이라도 실패하면 UI 미세 조정·내보내기보다 먼저 복구.
- **P1**: JSON/텍스트 내보내기, 기기별 사용성 다듬기, 익명 내보내기. 6주 이후 여유가 생기면 구현.
- **P2 / 8주 이후**: 실제 배포 로그인, 연구자 연결, 논문 검색, 연구 질의 생성 추천, 실험 자동화.

## 단계별 진행 방식

1. 착수 전에 현재 repo 조사, 해당 카드의 허용 범위·테스트와 변경 계획 요약.
2. 코드 변경 → lint/typecheck/unit/integration → E2E → 버그 수정.
3. 실제 수행한 명령과 테스트 결과를 Codex 답변에 남김. 테스트 환경이 없다면 미검증 표시.
4. 외부 API 과금 호출·배포·Git 원격 조작은 명시적인 승인 후 별도 실행.
5. 해당 단계가 완료되면 중단하고 사용자가 다음 카드를 요청할 때 진행.

## 일정 위험과 회피

| 위험 | 가능성/영향 | 대응 |
|---|---|---|
| 모델 출력이 6개 기준을 누락 | 중/높음 | strict JSON Schema + 사후 invariant 검사, mock 우선 개발 |
| 실제 연구 주제마다 평가 기준 적용이 부적합 | 중/높음 | `not_applicable` 및 불확실성 제시, 분야별 제한 명시 |
| 실제 학생 자료/멘토 섭외 어려움 | 높음/중간 | 합성 자료 테스트와 실제 사용성 평가 구별, 무리한 유효성 주장 금지 |
| DB·인증 구현으로 일정 초과 | 중/높음 | IndexedDB 로컬 우선; 로그인·공개 배포 제외 |
| 유료 API 접근 지연 | 중/중간 | deterministic fixture로 E2E·UI 완료 후 선택적 실모드 연동 |
| 비교 조건의 모델 차이 | 높음/높음 | 모델/날짜/프롬프트 기록, 통제 불완전성 명시 |

## 최종 완료 정의

PRD의 모든 P0 인수조건과 TEST_PLAN 핵심 E2E가 충족되고, 사전 고지·동의·삭제·실패 복원 동작을 시연할 수 있으며, 비교평가 프로토콜과 실제 수집 여부/제약이 분리되어 문서화된 상태.
